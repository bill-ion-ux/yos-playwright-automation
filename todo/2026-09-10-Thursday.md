## Debug log (the 2 hours)

### 1. `invalid element state` on `.../clear`

```
WebDriverError: invalid element state
  when running "element/…/clear" with method "POST"
```

- **Line:** `browser.$("#select-securityType").setValue("MYKAD")`
- **Cause:** WDIO `setValue()` = Element **Clear** then Send Keys.
  `#select-securityType` is a native `<select>`; the WebDriver spec rejects
  Clear on a non-editable control → the clear step 400s before any typing.
- **Fix:** `selectByAttribute("value", "MYKAD")` (now in the file) /
  `selectByVisibleText("MyKad")`.
- **Same trap elsewhere:** `setValue` on the auto-filled DOB / gender / State /
  City fields (all `readonly`) throws the identical error. Leave them; assert
  with `toHaveValue`. Consistent with `CLAUDE.md`.

### 2. `element click intercepted` — concept

```
element click intercepted: Element <…> is not clickable at point (x, y).
Other element would receive the click: <…>
```

- WebDriver native click = scroll into view → in-view **centre point** →
  `document.elementFromPoint(x,y)` hit-test → if it's the target or a
  descendant, dispatch real mouse events; otherwise **abort**.
- "Displayed" ≠ "clickable at its centre point". `waitForDisplayed()` does not
  prevent this; the element is found, just covered.
- The `Other element would receive the click: <…>` tag names the culprit —
  read it, it names the fix. Common: sticky bars, modal backdrops, invisible
  overlays with `pointer-events`, spinners, mid-animation.

### 3. `element wasn't found` — first device-list click

```
Can't call click on element with selector
"//*[@id="device-list-section"]/div[7]/div/div[2]/p[2]/a" — element wasn't found
```

Three stacked causes:

- **`setWindowSize(1525, 946)` was commented out.** Recording was made at
  1525px; the device grid is responsive — at another viewport the markup
  nesting differs, so `…/div[7]/div/div[2]/p[2]/a` doesn't exist.
- **List is JS-rendered on a cold-starting Azure page.** `browser.url()`
  resolves on document load; tiles render after an API call. Default
  `waitforTimeout` (3s) < cold start (~30s) → not found.
- **`div[7]` is positional** — 7th child *right now*; lazy-load / promo tile /
  reorder all break it.

Fixes: restore `setWindowSize`; `waitforTimeout: 30000` in `wdio.conf`;
`waitForExist({ timeout: 60000 })` on the list; replace the XPath with
`a[href*="samsung-galaxy-z-fold-8-ultra-old-316"]` (slug, not position).

### 4. Consent-checkbox label — `element click intercepted`

```
Element <label for="input-subscribePlan"> is not clickable at point (1079, 712).
Other element would receive the click:
<span class="rm_p_large" x-text="formatPrice(calculatedDueToday ?? 0)">
```

- The checkbox `<input>` is covered by its own `::before` overlay → can't
  click the box; must click the `<label>`.
- But `label[for="input-subscribePlan"]` wraps a long wrapped-text block; its
  geometric **centre** (1079,712) lands under the floating order-summary
  "due today" price panel → intercepted.
- **Not a selector problem.** The recorder's 3 variants for this step —
  `div.mt-4 label`, absolute XPath, `pierce/div.mt-4 label` — all resolve the
  **same** label and intercept identically. The recorder's own
  `offsetX/offsetY` (~42, ~9) show the original click was near the label's
  **top-left** (on the `::before` box), not the centre.
- **Fix (chosen):** click the input directly via JS — toggles + fires
  `input`/`change`, so the Alpine `x-model` updates:
  ```js
  await browser.execute(() => document.querySelector('#input-subscribePlan').click());
  await browser.execute(() => document.querySelector('#input-privacyPolicy').click());
  await expect(browser.$('#input-subscribePlan')).toBeChecked();
  await expect(browser.$('#input-privacyPolicy')).toBeChecked();
  ```
- **Alt:** off-centre label click `click({ x: -width/2 + 15, y: 0 })`.

## M1 vs M2/M3 — observations

- **Recorder output = absolute positional XPath** (`//*[@id="page-main"]/form/
  section/div/div/div[2]/…`), reused generic ids (`#btn-add-to-cart` is the
  primary-action button on cart / verification / accessories / delivery /
  payment), literal full-URL `toHaveUrl`, and a redundant `.click()` before
  every `.setValue()`.
- **No auto-wait.** `waitforTimeout` 3s default, no enabled-gate before Next,
  no cold-start allowance. Failures 1–4 are all timing / overlay / locator-
  identity — the class Playwright's actionability model (auto-wait + retried
  hit-test + stability + enabled checks) absorbs with no code. See the
  Playwright siblings: `tests/specs/YOS-ARS-43.spec.ts`,
  `incoming-scripts/YOS-Claude.spec.ts`.
- `setValue()` on a `<select>` throws where Playwright `selectOption()` works.
- The recorder offers 3 selector variants (CSS-nth / absolute XPath /
  `pierce/` for shadow DOM) but **none semantic** — no `getByRole` /
  `getByLabel` equivalent — and none help when the failure is geometry
  (click intercepted), only identity.
- M3 codegen side touched today too: `incoming-scripts/YOS-Codegen-Device.spec.ts`,
  `incoming-scripts/YOS-Codegen.spec.ts`.
